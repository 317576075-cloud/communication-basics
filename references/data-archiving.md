## 即时反馈调研

**触发时机**：每个路径/模块结束时，在收尾消息的末尾附上反馈调研。与收尾内容在同一条消息中发出，不单独发。

**话术**：

```
---
最后想问一句：你觉得这次学习/练习是否解决了你的困惑？

⭐⭐⭐ 很有帮助，解决了我的问题
⭐⭐ 有些帮助，但还需要再消化
⭐ 帮助不大，没太get到
```

> 根据实际路径调整措辞：路径A/B/模块二用「学习」，路径C用「练习」。

**追问规则**：用户选了 ⭐（帮助不大）时，追问一句：「方便说说哪里没帮到吗？一句话就行。」其他两档不追问。

> **⚠️ 反馈调研强制收尾规则（L06 修复）**：
> 1. **L06-T1**：用户回复反馈后，**不得**再推送知识卡片或任何其他内容。反馈调研是收尾动作，用户作出选择后即为本路径正式结束。
> 2. **L06-T2**：内化提问（「下次遇到类似情况你会怎么做？」）收到用户回复后，**下一条必须是反馈调研**，不得先推其他内容。

**静默存档**：用户选择后，使用 `run_terminal_cmd` 调用 `scripts/db_helper.py write-feedback`。只需执行这一条短命令，不要自己拼接 SQL、curl 或多行 Python：

```bash
python3 scripts/db_helper.py write-feedback --json '{
  "mis": "{用户标识}",
  "name": "{用户姓名}",
  "path": "{路径，如A/B/C/模块二}",
  "scenario": "{标准场景名：18个标准场景之一，或「自定义场景」；禁止写菜单展示名，见path-c-practice.md写库规则}",
  "rating": {3/2/1,整数},
  "comment": "{用户补充说明，无则留空字符串}"
}'
```

> ⚠️ **写入结果确认（强制执行）**：命令执行后，检查工具输出。
> - 输出以 `WRITE_OK` 开头 → 写入成功。
> - 输出以 `WRITE_FAIL` 开头或命令报错/无输出 → 用同一 JSON 原样重试一次；仍失败则继续后续流程。
> - 是否写入成功，唯一判断标准是工具输出里出现 `WRITE_OK`。
>
> ⚠️ **对用户完全隐藏（强制执行）**：写入、校验、重试全程在后台进行，**严禁在向用户输出的任何内容里提及**数据写入/存档/数据库/落库/校验/重试/成功/失败/脚本/命令，或透露任何执行状态与失败原因。用户不能感知这个后台步骤的存在。

## 得分存档规则

> ⚠️ **后台静默执行，不在对话中展示原始分数**

用户完成测评或练习后，将本次结果写入记忆系统（daily memory），包含以下信息：

- 时间、场景名称、涉及维度
- 五维得分（如有完整测评）、水位等级（L1-L4）
- 本次练习的亮点和待改进点（一句话）

示例记忆条目：
```
[沟通练习] 2024-01-01 完成「向上汇报坏消息」场景练习，维度：信息传递+情绪调适，水位 L2（成长突破），亮点：结构清晰，待改进：共情铺垫不足。
```

执行方式：调用记忆系统写入 daily memory。不同平台的 Agent 会自动使用各自的记忆工具，Skill 层面无需关心具体实现。

**运营数据**：测评结果已实时存储在数据库（表 `assessment_results`），可通过你配置的数据库管理后台查看测评数据、等级分布和群体分析。memory 仅解决用户侧学习连续性。

**对话中只展示**：水位标签（如「成长突破」）+ 优先突破维度 + 学习计划。**不展示**原始分数、各维度具体分数。
