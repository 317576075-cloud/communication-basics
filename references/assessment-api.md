AI 通过 `scripts/db_helper.py` 查询测评结果。此接口在「第一步：判断入口」的前置动作中静默调用，也在模块一流程中复用。

## 查询方式

使用终端命令调用脚本（将 `{user_id}` 替换为用户的用户标识）：

```bash
python3 scripts/db_helper.py query-assessment --mis {user_id}
```

> 返回 JSON 对象 `{"success": true, "found": true/false, "data": {...}}`。`found=true` 时 `data` 含测评记录；`found=false` 时 `data` 为 `null`。
> ⚠️ **错误处理**：如果 `success=false` 或脚本报错，不要重试，直接走兜底方案——提示用户手动回传分数。

## 返回数据格式

JSON 对象，`data` 字段含最新记录：
```json
{
  "success": true,
  "found": true,
  "data": {
    "name": "张三",
    "mis": "zhangsan",
    "d1": 75,
    "d2": 68,
    "d3": 80,
    "d4": 65,
    "d5": 70,
    "total": 72,
    "grade": "良好",
    "created_at": "2026-04-28T15:21:59"
  }
}
```

**字段映射**：d1=影响推动，d2=关系建设，d3=信息传递，d4=人际感知，d5=情绪调适。

## 获取用户标识

优先从当前平台的用户信息中获取（有会话/用户资料能力的平台可直接读取）。如果无法自动获取，直接问用户：「请告诉我你的用户标识，我来查你的测评结果。」

## 执行方式

根据前置查询结果分流：

**情况 A：已有测评记录**

前置查询返回 `found=true`，说明用户已经做过测评。从 `data` 字段提取五维分数，跳过测评引导，进入「解读结果 & 输出学习计划」。

**情况 B：无测评记录**

前置查询返回 `found=false`（`data` 为 `null`），引导用户去做测评：

```
我来帮你做一个沟通能力的全面摸底。

这是一份 20 题的情景测评，覆盖 5 个能力维度，大约 15 分钟。
完成后我会自动获取你的结果，给你制定一个专属学习计划。

👉 [开始测评]（待补充）

做完之后回来告诉我一声就行，我会自动读取你的成绩。
```

用户回来后（说「做完了」「测完了」或任何后续消息），再次调用 `db_helper.py query-assessment`。返回 `found=true` 则进入解读，仍为 `found=false` 则提示「还没查到你的测评记录，可能还没提交成功，你也可以直接告诉我分数。」

> **注**：测评页面需自行部署或接入（链接见上方占位）。如需更新测评内容，请在你的测评系统中编辑。

## 兜底：手动回传

如果自动查询失败或用户主动报分数，以下格式均视为测评结果回传，直接进入解读：
- 「综合 72，影响推动 75，关系建设 68，信息传递 80，人际感知 65，情绪调适 70」
- 截图（AI 读取图中数字）
- 「我做完了，总分 72」（无五维时，按总分判断水位，提示用户补充五维分数以获得更精准计划）
